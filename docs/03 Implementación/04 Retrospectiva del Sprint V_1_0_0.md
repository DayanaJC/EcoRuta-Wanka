## ¿Qué aprendimos?

* Aprendimos que es importante probar con anticipación los servicios que vamos a utilizar para evitar problemas durante el desarrollo.
* Aprendimos que los cambios importantes deben conversarse antes de realizarlos, porque pueden aumentar el tiempo de trabajo.
* Aprendimos que debemos tener claras las necesidades del sistema antes de comenzar cada tarea.
* Aprendimos que las pruebas ayudan a encontrar errores antes de presentar el sistema.
* Aprendimos que debemos comprobar que las funciones desarrolladas realmente cumplen con lo que necesita el usuario.

## ¿Qué estamos haciendo bien?

* Se completaron las tres historias de usuario planificadas para el Sprint.
* Se logró completar los **23 de 23 puntos** planificados.
* El equipo logró avanzar en la gestión de vehículos, pedidos y generación de rutas.
* Se realizaron pruebas para comprobar que las funciones principales trabajan correctamente.
* Se logró mostrar el sistema funcionando para realizar una demostración.
* Se mantuvo comunicación entre los integrantes para resolver los problemas encontrados durante el Sprint.

## ¿Qué podemos hacer mejor?

### Personas

* Repartir mejor las tareas entre los integrantes.
* Procurar que ambos integrantes conozcan las diferentes partes del proyecto.
* Apoyarnos entre todos cuando una tarea presente dificultades.

### Relaciones

* Conversar antes de realizar cambios importantes en el proyecto.
* Mantener una comunicación más frecuente durante el desarrollo.
* Compartir los avances y problemas encontrados.
* Pedir y dar opiniones antes de tomar decisiones importantes.

### Procesos

* Revisar las tareas antes de comenzar cada Sprint.
* Definir claramente qué se debe lograr en cada historia de usuario.
* Realizar revisiones durante el desarrollo y no solamente al finalizar.
* Dividir las tareas grandes en actividades más pequeñas y fáciles de controlar.

### Herramientas

* Realizar pruebas de las funciones antes de presentar el sistema.
* Comprobar que el sistema funcione correctamente después de cada cambio importante.
* Mejorar las pruebas de la parte visual de la aplicación.
* Contar con un espacio de prueba antes de realizar cambios en la versión final.
