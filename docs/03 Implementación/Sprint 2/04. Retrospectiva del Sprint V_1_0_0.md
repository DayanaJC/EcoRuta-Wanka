## ¿Qué aprendimos?

* Aprendimos que las nuevas funcionalidades deben probarse junto con las funcionalidades desarrolladas anteriormente para comprobar que el sistema continúe funcionando correctamente.
* Aprendimos que los indicadores de sostenibilidad deben utilizar la información registrada en el sistema para que los resultados mostrados sean coherentes.
* Aprendimos que la asignación de conductores debe verificarse junto con las rutas disponibles antes de finalizar la funcionalidad.
* Aprendimos que realizar pruebas durante el desarrollo permite detectar y corregir observaciones antes de finalizar cada historia de usuario.

## ¿Qué estamos haciendo bien?

* Se mantuvo una buena comunicación entre los integrantes durante el desarrollo del Sprint.
* Se distribuyeron las actividades de acuerdo con las necesidades de las historias de usuario.
* Se completaron las cuatro historias de usuario planificadas.
* Se completaron los **29 de 29 puntos** planificados.
* Se implementó la visualización de las rutas en el mapa.
* Se implementaron el dashboard y el reporte de sostenibilidad.
* Se implementó el registro y asignación de conductores a las rutas.
* Se realizaron pruebas para verificar el funcionamiento de las nuevas funcionalidades junto con las desarrolladas anteriormente.

## ¿Qué podemos hacer mejor?

### Personas

El equipo tuvo una buena organización y logró completar las actividades planificadas. Como mejora, se continuará definiendo desde el inicio de cada historia qué actividad realizará cada integrante, para mantener una distribución clara del trabajo durante el Sprint.

### Relaciones

La comunicación entre los integrantes fue adecuada y permitió avanzar con las actividades sin mayores dificultades. Como mejora, se mantendrá la comunicación frecuente sobre los avances y se informará oportunamente cualquier observación para resolverla antes de que afecte el desarrollo.

### Procesos

El Sprint se completó según lo planificado. Como mejora, se reforzará la revisión de los criterios de aceptación y las pruebas antes de marcar una historia como terminada, verificando que cada funcionalidad cumpla con lo establecido.

### Herramientas

Las herramientas utilizadas permitieron desarrollar, probar y verificar las funcionalidades del Sprint. Como mejora, se continuará realizando pruebas después de cambios importantes y se reforzarán las pruebas de las principales pantallas del sistema.
