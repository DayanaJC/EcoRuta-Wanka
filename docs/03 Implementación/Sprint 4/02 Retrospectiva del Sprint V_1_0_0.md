## ¿Qué aprendimos?

- Aprendimos que los avisos no deben afectar el registro de los pedidos o las entregas. Aunque ocurra un error al guardar un aviso, la operación principal debe continuar.
- Aprendimos que los enlaces públicos permiten que los clientes consulten sus pedidos sin necesidad de crear una cuenta.
- Aprendimos que utilizar WhatsApp mediante un enlace facilita la comunicación con los clientes sin necesitar servicios adicionales de pago.
- Aprendimos que las nuevas funcionalidades deben organizarse antes de comenzar a desarrollarlas, para evitar desorden durante el trabajo.
- Aprendimos que es importante revisar las dependencias del proyecto antes de ejecutar el sistema para evitar errores durante su funcionamiento.

## ¿Qué estamos haciendo bien?

- Se mantuvo una buena comunicación y coordinación entre los dos integrantes durante el Sprint.
- Se trabajó utilizando ramas y Pull Requests para organizar los cambios del proyecto.
- Se completó la integración de las nuevas funcionalidades de avisos entre el frontend y el backend.
- Se realizaron **10 pruebas nuevas**, alcanzando un total de **125 de 125 pruebas aprobadas en el backend**.
- Se mantuvo un buen rendimiento del sistema después de las mejoras realizadas:
  - LCP de **0,59 a 0,88 segundos** y TTFB de **0,27 a 0,31 segundos** en la página principal.
  - La API presentó tiempos de respuesta de **0,25 a 0,28 segundos**.
- Las pruebas automáticas con Playwright aprobaron **79 de 79** en Chromium, Firefox y WebKit.
- Los mensajes de los avisos se redactaron con palabras sencillas y cercanas, pensando en las bodegas y comercios de Huancayo.
- Se mantuvo organizada la documentación y las evidencias correspondientes al Sprint.
