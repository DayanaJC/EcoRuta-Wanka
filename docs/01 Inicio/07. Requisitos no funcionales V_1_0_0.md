## 1. Enfoque de definición

Los requisitos no funcionales de **EcoRuta Wanka** establecen las condiciones de calidad que debe cumplir el sistema. Se relacionan principalmente con el rendimiento, seguridad, usabilidad, disponibilidad, mantenibilidad, compatibilidad y exactitud de la información.

Cada requisito se define mediante una condición verificable y una medida que permita comprobar su cumplimiento.

Los requisitos se organizan tomando como referencia las características de calidad establecidas en **ISO/IEC 25010**.

# 3. Escenarios de calidad

## RNF-01. Eficiencia de desempeño

**Fuente:** Usuario del sistema.
**Estímulo:** Solicitud de consulta o generación de una ruta.
**Entorno:** Uso normal del sistema con los datos definidos para las pruebas.
**Artefacto:** Funciones relacionadas con la gestión y generación de rutas.
**Respuesta:** El sistema debe procesar la solicitud y mostrar el resultado.
**Medida:** El 95 % de las operaciones principales deberá completarse en un máximo de **45 segundos** durante las pruebas.

---

## RNF-02. Seguridad

**Fuente:** Usuario autorizado o intento de acceso no autorizado.
**Estímulo:** Inicio de sesión o intento de acceder a una función protegida.
**Entorno:** Uso normal del sistema.
**Artefacto:** Módulo de autenticación y control de acceso.
**Respuesta:** El sistema debe permitir o rechazar el acceso según las credenciales y permisos del usuario.
**Medida:** El 100 % de las funciones protegidas deberá requerir autenticación y autorización correspondiente. Las pruebas de seguridad no deberán presentar vulnerabilidades críticas conocidas.

**Relación funcional:** RF-10 – Autenticación y control por roles.

---

## RNF-03. Usabilidad y accesibilidad

**Fuente:** Usuarios del sistema.
**Estímulo:** Realización de las operaciones principales del sistema.
**Entorno:** Pruebas con dispositivos definidos para el proyecto.
**Artefacto:** Interfaz del sistema.
**Respuesta:** El sistema debe presentar la información de forma clara y permitir completar las tareas principales.
**Medida:** Al menos el **90 % de los usuarios de prueba** deberá completar las tareas principales sin asistencia directa.

---

## RNF-04. Exactitud de la información

**Fuente:** Administrador u operador.
**Estímulo:** Consulta de información e indicadores generados a partir de datos registrados.
**Entorno:** Uso normal con información previamente validada.
**Artefacto:** Módulos de indicadores y reportes.
**Respuesta:** El sistema debe mostrar resultados coherentes con los datos registrados y las reglas de cálculo establecidas.
**Medida:** La diferencia respecto a los valores de referencia deberá ser como máximo de **5 %** en los casos de prueba.

**Relación funcional:** RF-05 – Indicadores de sostenibilidad y RF-06 – Reportes de sostenibilidad.

---

## RNF-05. Usabilidad y satisfacción

**Fuente:** Usuarios participantes de las pruebas de aceptación.
**Estímulo:** Uso de las funciones principales del sistema.
**Entorno:** Sesión de prueba con usuarios y dispositivos definidos.
**Artefacto:** Interfaz del sistema.
**Respuesta:** Los usuarios deben poder completar las tareas principales y comprender las opciones disponibles.
**Medida:** Al menos el **90 % de los usuarios de prueba** deberá obtener una valoración de **4 sobre 5 o superior** en la evaluación de usabilidad.

**Relación con el proyecto:** O5 – Obtener una valoración de usabilidad de al menos 4 sobre 5 en las pruebas con usuarios.

---

## RNF-06. Fiabilidad y disponibilidad

**Fuente:** Usuario del sistema.
**Estímulo:** Acceso y utilización del sistema durante el periodo de operación definido.
**Entorno:** Uso normal del sistema.
**Artefacto:** Sistema completo y servicios de almacenamiento de información.
**Respuesta:** El sistema debe permanecer disponible y conservar correctamente la información registrada.
**Medida:** La disponibilidad objetivo será de al menos **99 % mensual** durante el periodo definido para las pruebas.

---

## RNF-07. Cumplimiento de reglas de negocio

**Fuente:** Administrador u operador.
**Estímulo:** Realización de una operación que está sujeta a una regla de negocio.
**Entorno:** Uso normal del sistema.
**Artefacto:** Funciones de gestión de vehículos, pedidos, rutas y asignaciones.
**Respuesta:** El sistema debe validar las condiciones establecidas antes de completar la operación.
**Medida:** El **100 % de los casos de prueba** relacionados con las reglas de negocio deberá producir el resultado esperado.

**Relación funcional:** RF-01, RF-02, RF-03, RF-07 y RF-08.

---

## RNF-08. Mantenibilidad

**Fuente:** Equipo de desarrollo.
**Estímulo:** Necesidad de corregir un defecto o realizar un cambio en una funcionalidad.
**Entorno:** Ciclo de desarrollo y mantenimiento del proyecto.
**Artefacto:** Código fuente y componentes del sistema.
**Respuesta:** Los cambios deben poder realizarse de forma organizada sin afectar innecesariamente otras funcionalidades.
**Medida:** Los cambios realizados deberán contar con revisión del código y pruebas correspondientes antes de integrarse a la versión del proyecto.

---

## RNF-09. Compatibilidad

**Fuente:** Usuario del sistema.
**Estímulo:** Acceso desde diferentes navegadores y dispositivos.
**Entorno:** Pruebas de compatibilidad definidas para el proyecto.
**Artefacto:** Interfaz web del sistema.
**Respuesta:** El sistema debe mostrar correctamente sus funciones principales y permitir su utilización sin errores que bloqueen la operación.
**Medida:** Se deberá verificar el funcionamiento de las funciones principales en al menos **2 navegadores de escritorio y 2 navegadores móviles** seleccionados para las pruebas.

# 7. Criterios generales de validación

Los requisitos no funcionales deberán verificarse mediante pruebas, métricas, revisiones o auditorías según corresponda.

Para su validación:

1. Cada RNF debe contar con una medida verificable.
2. Las métricas deben utilizar valores definidos antes de realizar las pruebas.
3. Los resultados de las pruebas deberán registrarse como evidencia del cumplimiento.
4. Los incumplimientos deberán registrarse para su corrección y posterior verificación.
5. Los valores establecidos en este documento representan criterios objetivo del proyecto.
