## 1. Objetivo del documento

Este documento presenta las tecnologías seleccionadas para desarrollar EcoRuta Wanka y explica los criterios utilizados para elegirlas.

La selección considera el tipo de proyecto, el tamaño del equipo, el presupuesto académico, el plazo de desarrollo, la necesidad de trabajar con una aplicación web y el uso de servicios en la nube.

El stack tecnológico se organiza de acuerdo con la **Arquitectura por Capas** definida para el proyecto:

```text
Frontend
    ↓
Capa de Presentación
    ↓
Capa de Negocio
    ↓
Capa de Datos
    ↓
Firebase Cloud Firestore
```

## 3. Alternativas tecnológicas

Se consideraron tres alternativas principales para el desarrollo del sistema.

| Alternativa | Backend           | Frontend | Base de datos            |
| ----------- | ----------------- | -------- | ------------------------ |
| A1          | Node.js + Express | React    | MongoDB                  |
| A2          | Python + FastAPI  | React    | PostgreSQL               |
| A3          | Python + FastAPI  | React    | Firebase Cloud Firestore |

La alternativa A3 fue seleccionada debido a su compatibilidad con el proyecto, facilidad de desarrollo, disponibilidad de servicios en la nube y adecuación al presupuesto académico.

## 5. Stack tecnológico seleccionado

El stack tecnológico seleccionado para EcoRuta Wanka es:

### 5.1 Frontend

**React + Vite**

Se utilizará para desarrollar la interfaz web del sistema.

Sus principales funciones son:

* Mostrar información de vehículos y pedidos.
* Permitir la interacción de los usuarios con el sistema.
* Mostrar las rutas generadas.
* Presentar indicadores y reportes.
* Facilitar la navegación entre las diferentes funcionalidades.

**Tecnologías:**

| Tecnología | Uso                                                 |
| ---------- | --------------------------------------------------- |
| React      | Desarrollo de la interfaz web.                      |
| Vite       | Entorno de desarrollo y construcción del frontend.  |
| JavaScript | Lenguaje utilizado para el desarrollo del frontend. |
| oxlint     | Revisión y control de calidad del código.           |

---

### 5.2 Backend

**Python + FastAPI**

FastAPI se utilizará para desarrollar los servicios del backend y las API que conectan el frontend con la información almacenada.

Sus principales funciones son:

* Gestionar las solicitudes del sistema.
* Validar la información recibida.
* Aplicar las reglas de negocio.
* Gestionar vehículos, pedidos, asignaciones y rutas.
* Conectar las capas de negocio y datos.

| Tecnología | Uso                                      |
| ---------- | ---------------------------------------- |
| Python     | Lenguaje principal del backend.          |
| FastAPI    | Desarrollo de servicios y API REST.      |
| Pydantic   | Validación y manejo de datos.            |
| Uvicorn    | Ejecución del servidor de la aplicación. |

---

### 5.3 Base de datos

**Firebase Cloud Firestore**

Firestore será utilizado como sistema de almacenamiento de información del proyecto.

Permitirá almacenar información relacionada con:

* Vehículos.
* Pedidos.
* Asignaciones.
* Rutas.
* Conductores.
* Preferencias.
* Información necesaria para indicadores y reportes.

La utilización de un servicio administrado reduce la necesidad de configurar y mantener un servidor de base de datos propio.

---

### 5.4 Servicios de Firebase

El proyecto utilizará servicios de Firebase de acuerdo con las necesidades de sus funcionalidades.

| Servicio                | Uso                                                  |
| ----------------------- | ---------------------------------------------------- |
| Cloud Firestore         | Almacenamiento de información.                       |
| Firebase Admin SDK      | Acceso a Firestore desde el backend.                 |
| Firebase Authentication | Control de autenticación de usuarios.                |
| Firebase Hosting        | Publicación de la aplicación web cuando corresponda. |

---

### 5.5 Pruebas

**Pytest**

Se utilizará Pytest para realizar pruebas del backend y comprobar el correcto funcionamiento de las funcionalidades principales.

Las pruebas permitirán verificar principalmente:

* Reglas de negocio.
* Validación de datos.
* Operaciones de vehículos.
* Operaciones de pedidos.
* Asignaciones.
* Generación de rutas.
* Comportamiento de los servicios.

---

### 5.6 Control de versiones

**Git + GitHub**

Git y GitHub se utilizarán para controlar las versiones del proyecto y organizar el trabajo del equipo.

Se utilizarán ramas para separar el desarrollo de nuevas funcionalidades y facilitar la integración de los cambios.

## 6. Relación con la arquitectura por capas

Las tecnologías seleccionadas se relacionan con la arquitectura del proyecto de la siguiente manera:

| Capa         | Tecnología               | Función                                            |
| ------------ | ------------------------ | -------------------------------------------------- |
| Presentación | React + Vite             | Interfaz con la que interactúa el usuario.         |
| Negocio      | Python + FastAPI         | Procesamiento de reglas y operaciones del sistema. |
| Datos        | Python + repositorios    | Gestión del acceso a la información.               |
| Persistencia | Firebase Cloud Firestore | Almacenamiento de los datos.                       |

Esta separación permite que cada capa tenga una responsabilidad definida y facilita el mantenimiento del sistema.

## 7. Justificación del stack seleccionado

### Facilidad de desarrollo

Python, FastAPI y React permiten desarrollar una aplicación web utilizando tecnologías ampliamente utilizadas y con abundante documentación.

### Costo

Firebase ofrece servicios que pueden utilizarse para un proyecto académico con un consumo controlado, reduciendo la necesidad de administrar infraestructura propia.

### Mantenibilidad

La separación entre presentación, negocio y datos permite realizar cambios en una parte del sistema sin modificar innecesariamente las demás capas.

### Escalabilidad

Firestore proporciona una base de datos administrada que permite ampliar el sistema sin tener que administrar directamente un servidor de base de datos.

### Integración

FastAPI permite crear los servicios que serán consumidos por React, mientras que el backend puede acceder a Firestore mediante el Firebase Admin SDK.

### Adecuación al proyecto

El stack seleccionado permite cubrir las principales necesidades de EcoRuta Wanka: gestión de vehículos, pedidos, asignaciones, rutas, conductores, preferencias, indicadores y reportes.

## 9. Conclusión

El stack seleccionado para EcoRuta Wanka está conformado por **React + Vite para el frontend, Python + FastAPI para el backend y Firebase Cloud Firestore para la persistencia de datos**.

La selección responde a las características del proyecto académico, al presupuesto disponible, al tamaño del equipo y a la necesidad de desarrollar una aplicación web mantenible y escalable.

Además, las tecnologías seleccionadas se integran con la **Arquitectura por Capas**, permitiendo separar la presentación, la lógica de negocio y el acceso a los datos.
