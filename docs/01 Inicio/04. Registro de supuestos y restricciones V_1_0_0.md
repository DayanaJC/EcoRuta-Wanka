## 1. Introducción

Este documento registra los supuestos y restricciones considerados para la planificación y desarrollo de EcoRuta Wanka.

Los **supuestos** corresponden a condiciones que se consideran válidas para planificar el proyecto y que deben ser verificadas durante su ejecución.

Las **restricciones** corresponden a condiciones que limitan las alternativas disponibles para el desarrollo y ejecución del proyecto.

---

## 2. Registro de supuestos

| ID        | Descripción                                                                                                                                   | Categoría  | Grado de Impacto | Estrategia de Validación                                                                  |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ---------- | ---------------- | ----------------------------------------------------------------------------------------- |
| **AS-01** | El equipo de desarrollo dispondrá de computadoras adecuadas para ejecutar las herramientas necesarias del proyecto.                           | Técnica    | Alto             | Verificar la disponibilidad y capacidad de los equipos durante las iteraciones.           |
| **AS-02** | Firebase/Firestore estará disponible para almacenar y consultar la información utilizada por el sistema.                                      | Técnica    | Alto             | Realizar pruebas de conexión y disponibilidad durante el desarrollo.                      |
| **AS-03** | Los usuarios dispondrán de conexión a Internet para utilizar la aplicación web y acceder a los servicios en la nube.                          | Operativa  | Medio            | Verificar la conectividad durante las pruebas de funcionamiento.                          |
| **AS-04** | Los pedidos registrados contendrán la información necesaria para su gestión y planificación de rutas.                                         | Operativa  | Alto             | Validar los campos obligatorios durante el registro de pedidos.                           |
| **AS-05** | Los vehículos registrados contarán con información sobre tipo, placa, capacidad y estado operativo.                                           | Operativa  | Alto             | Validar los datos mediante las reglas de negocio definidas.                               |
| **AS-06** | Los pedidos destinados a la generación de rutas contarán con coordenadas geográficas válidas.                                                 | Técnica    | Alto             | Validar las coordenadas durante el registro y procesamiento de los pedidos.               |
| **AS-07** | Las reglas de negocio definidas para vehículos, pedidos y asignaciones representan el proceso logístico considerado para el proyecto.         | Operativa  | Medio            | Validar las reglas mediante pruebas y demostraciones funcionales.                         |
| **AS-08** | Los integrantes del equipo podrán participar en las actividades de análisis, desarrollo, pruebas y control de versiones.                      | Operativa  | Alto             | Realizar seguimiento de actividades, ramas, commits y Pull Requests.                      |
| **AS-09** | Las herramientas y tecnologías seleccionadas estarán disponibles durante el periodo de desarrollo académico.                                  | Técnica    | Medio            | Revisar periódicamente la compatibilidad y disponibilidad de las herramientas utilizadas. |
| **AS-10** | Los costos asociados a los servicios utilizados durante el desarrollo se mantendrán dentro del presupuesto académico disponible.              | Financiera | Medio            | Realizar seguimiento periódico de los costos de servicios y recursos externos.            |
| **AS-11** | El proceso de generación de rutas podrá utilizar la información disponible de pedidos, vehículos y ubicaciones para producir rutas válidas.   | Técnica    | Alto             | Validar los resultados mediante casos de prueba y escenarios controlados.                 |
| **AS-12** | Los indicadores de distancia, consumo de combustible y emisiones de CO₂ podrán utilizarse como estimaciones para evaluar las rutas generadas. | Operativa  | Medio            | Comparar los cálculos con escenarios de prueba y verificar las fórmulas utilizadas.       |

## 3. Registro de restricciones

| ID        | Descripción                                                                                                                              | Categoría  | Severidad | Flexibilidad de Negociación |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ---------- | --------- | --------------------------- |
| **CO-01** | El proyecto debe desarrollarse dentro del periodo establecido por la asignatura.                                                         | Tiempo     | Alta      | Baja                        |
| **CO-02** | El alcance del proyecto está limitado a las funcionalidades priorizadas para el Producto Mínimo Viable (PMV).                            | Tiempo     | Alta      | Media                       |
| **CO-03** | El sistema debe mantener una separación entre frontend y backend de acuerdo con la estructura definida para el proyecto.                 | Tecnología | Alta      | Baja                        |
| **CO-04** | El backend utilizará FastAPI y el almacenamiento principal utilizará Firebase Firestore.                                                 | Tecnología | Media     | Media                       |
| **CO-05** | El frontend utilizará React y Vite para la implementación de la aplicación web.                                                          | Tecnología | Media     | Media                       |
| **CO-06** | El funcionamiento del sistema depende de servicios externos de infraestructura en la nube, principalmente Firebase/Firestore.            | Tecnología | Alta      | Media                       |
| **CO-07** | El proyecto cuenta con un presupuesto académico limitado para servicios, infraestructura y herramientas externas.                        | Costo      | Media     | Media                       |
| **CO-08** | La generación de rutas depende de la información registrada sobre pedidos, vehículos, ubicaciones y condiciones de entrega.              | Operativa  | Alta      | Media                       |
| **CO-09** | Los pedidos sin coordenadas geográficas válidas no podrán utilizarse directamente para generar una ruta optimizada.                      | Tecnología | Alta      | Baja                        |
| **CO-10** | El desarrollo debe mantener el control de versiones mediante GitHub, ramas y Pull Requests.                                              | Tecnología | Media     | Baja                        |
| **CO-11** | El repositorio no debe contener credenciales, claves privadas ni otros datos sensibles utilizados por los servicios del sistema.         | Normativa  | Alta      | Baja                        |
| **CO-12** | La aplicación debe considerar criterios de accesibilidad, usabilidad y buenas prácticas de desarrollo web establecidos para el proyecto. | Normativa  | Media     | Media                       |
| **CO-13** | La disponibilidad de los integrantes puede estar condicionada por otras actividades académicas durante el periodo del proyecto.          | Tiempo     | Media     | Media                       |
| **CO-14** | La generación de rutas estará limitada por la calidad y disponibilidad de la información registrada en el sistema.                       | Operativa  | Alta      | Media                       |
